## Why

Every flight list in the app renders a six-column table inside a horizontal scroller. At 390 px the table cuts off after the third column, so on `/current-flights` the Status column and the emergency badge — the whole reason a dispatcher opens that page — sit off-screen behind a scroll almost nobody performs. The same table also carries columns that earn nothing: `/finished-flights` prints `CLOSED` on every row, and it shows the *scheduled* off-block for flights that already have a populated `timesheet.actual`.

Radical simplification fixes both problems at once. Four columns of two lines each fit inside 355 px, which is what makes the list driveable on a phone without a separate mobile rendering.

## What Changes

- Introduce one shared flight-list row: a `<Link>` laid out with CSS grid, four content columns plus a chevron, reflowing between mobile and `sm` without a second component.
- Columns become **Date** (ICAO date over off-block time), **Flight** (operator tail fin, callsign over aircraft registration), **Route** (IATA → IATA over departure airport name → destination airport name), and a **trailing** slot that is block/air time on finished lists and flight status on upcoming/current lists.
- **BREAKING (display):** lists lead with the **callsign** (`AAL4905`) instead of the flight number (`AA4905`).
- Finished lists read `timesheet.actual` instead of `timesheet.scheduled`.
- The whole row navigates to the flight, while the IATA codes still open their airports and the registration still opens its aircraft — done with an overlay link rather than nested anchors. The `View` column, the aircraft photo, the airframe name and the `Status` column on finished lists are removed.
- Rows are list semantics — `<ul>`/`<li>` around the links, with a visually hidden per-row label so a screen reader hears one flight rather than four loose fragments.
- Add a `1:47`-style duration formatter; `formatDuration` (`1h 45m`) and `getTimeDifferenceInHours` (`01:47`) both miss the target format.
- `FlightHistoryListTable` and `FlightHistoryListElement` are deleted; `/flight-history` uses the shared row.
- Two adjacent fixes: `SectionHeader` moves from `text-gray-600` to `text-gray-800` (the only page title in the app not already there, correcting 11 pages), and the hand-rolled emergency chip becomes a themed `<Badge>`.

## Capabilities

### New Capabilities

- `flight-list-row`: the shared row used by every flight list — its four columns, the mode-specific trailing slot, responsive behaviour, row navigation targets and accessible naming.

### Modified Capabilities

None. No existing spec describes the flight list tables.

## Impact

**Replaced**

- `app/features/flight/components/Table/FlightListTable.tsx`
- `app/features/flight/components/Table/FlightListElement.tsx`
- `app/features/flight/components/Table/FlightHistoryListTable.tsx`
- `app/features/flight/components/Table/FlightHistoryListElement.tsx`

**Routes affected**

- `/flights` (upcoming), `/current-flights`, `/finished-flights` (Operations), `/flight-history` (CabinCrew)
- `/operators/{id}/aircraft/{id}` — the aircraft's Flight history card adopts the same row shape. Its payload (`FlightHistoryEntry`) has no callsign, city or registration, so it shows the flight number and airport names, and reposition entries render as rows with a `Reposition` badge and no row link.

**Assets**

- `app/assets/operator/transparent/` — 149 tail fins with the white background removed, trimmed and quantized (616 KB, replacing 4.1 MB of JPGs at render time). Generated by `bin/make_transparent_fins.py`. The source `thumb/*.jpg` set (149 files, 4.1 MB) is deleted — it had no remaining references and stays recoverable from git history.

**Touched**

- `app/shared/lib/time.ts` — new clock-style duration formatter
- `app/shared/ui/Section/SectionHeader.tsx` — title colour
- `app/features/flight/components/Table/FlightListView.tsx` — renders the new list
- `app/features/airport/components/Airport/AirportRoute.tsx` — still used by `/travels`, left in place
- `app/features/aircraft/components/AircraftDetails/AircraftFlightHistoryCard.tsx` — rebuilt on a grid row; new `AircraftHistoryRow`

**Not affected**

- `TravelLogTable`, `AircraftListTable` and the rotation lists keep their current shape. `AircraftListTable` stays on the table-plus-cards pattern until someone migrates it.

**Data**

- No API change. `callsign`, `airport.name` and `timesheet.actual` are already on the flight response.
